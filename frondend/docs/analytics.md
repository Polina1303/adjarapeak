# Аналитика Adjara Peak

События отправляются в существующий `window.dataLayer`; подключённый GTM сохранён. Отправка данных во внешнюю систему выполняется существующими настройками GTM. Само добавление события не создаёт тег или конверсию в GTM.

| Событие | Триггер | Поля |
| --- | --- | --- |
| `click_phone` | Переход по `tel:` | `page_path` |
| `click_whatsapp` | Ссылка WhatsApp | `page_path` |
| `click_telegram` | Ссылка Telegram | `page_path` |
| `click_telegram_climbing` | Существующая ссылка `t.me/shpaksn` вне страниц походов | `page_path` |
| `click_category_tile` | Плитка магазина или проката на главной | `category_name`, `destination`, `page_path` |
| `click_ski_banner` | Кнопки зимнего слайда или баннера из фитнеса | `destination`, `page_path` |
| `click_fitness_banner` | Кнопка фитнес-блока или баннера из горнолыжного каталога | `destination`, `page_path` |
| `add_to_cart` | Успешное добавление товара, проката или подарочной карты | `category`, `ecommerce.currency`, `ecommerce.value`, `ecommerce.items[]` |

`item_category` — slug известной категории/раздела либо настоящий `category_id` для общей карусели, где названия категории нет в ответе каталога; `gift_card` для подарочных карт. `items[]` содержит ID, название, цену и добавленное количество. Повторное нажатие «В корзине» и изменение количества не считаются новым добавлением.

Клик по записи на скалы отправляет общее событие Telegram и отдельное событие скалолазания, по одному каждого типа. Кнопка и адрес записи не изменены. Один глобальный обработчик снимается при смене маршрута, поэтому SPA-переходы не накапливают обработчики.

Контактные данные покупателей, содержимое форм, текст сообщений, токены и параметры поисковых запросов в события не передаются. Для навигации сохраняется только pathname.

Проверка: открыть GTM Preview, нажать нужную ссылку и проверить имя события и поля. Для `add_to_cart` проверить количество и GEL в ecommerce. Не создавать реальные заявки при тестировании.
